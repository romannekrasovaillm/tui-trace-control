# Контроль TUI-агентов по локальным трейсам

Версия набора: 1.0.0 · 13 сентября 2026 · Язык инструкций: русский.

Восемь скиллов в формате `SKILL.md` задают процесс наблюдения, расследования и реакции на действия терминальных ИИ-агентов. Они работают с доступными журналами сообщений, вызовов и результатов инструментов и с независимыми артефактами. Скрытая chain-of-thought не требуется; доступный reasoning служит дополнительным сигналом.

## Что находится в архиве

| Скилл | Задача | Основные ресурсы |
| --- | --- | --- |
| `tui-trace-setup` | Определить границы задачи, источники и полномочия контроля | Протокол v1, контракт JSON, три тестовых трейса, основания подхода |
| `tui-trace-ingest` | Собрать, нормализовать и проверить непрерывность журналов | Карта адаптеров, правила ротации, курсоров и защиты исходных данных |
| `tui-trace-watch` | Обнаруживать структурные нарушения и потерю наблюдаемости | Локальный сканер Python, 40 тестов, правила и описание CLI |
| `tui-trace-audit` | Разобрать инъекцию, обход ограничений или сомнительный отчёт | Карточка находки, разделение намерения, попытки и результата |
| `tui-trace-contain` | Прекратить разрешённым способом опасные действия конкретного запуска | Порядок проверки процесса, сохранение доказательств и отчёт инцидента |
| `tui-trace-resume` | Проверить условия продолжения после паузы | Условия выпуска, связь запусков и история решений |
| `tui-trace-verify` | Сверить результат задачи, отчёт агента и фактические артефакты | Матрица приёмки |
| `tui-trace-evaluate` | Проверить обнаружение, ложные тревоги и реальную блокировку | Синтетические сценарии и метрики |

Каталоги находятся в `skills/`. В каждом есть YAML frontmatter с полями `name` и `description`, инструкции `SKILL.md` и метаданные `agents/openai.yaml`. Дополнительные ресурсы связаны относительными ссылками. Результаты выполненных проверок — в `VALIDATION_RU.md`, контрольные суммы — в `MANIFEST.sha256`.

## Подключение к TUI

Скопируйте нужные каталоги из `skills/` целиком в каталог скиллов вашего TUI, сохранив вложенные файлы. Конкретное расположение и механизм загрузки определяются клиентом. Если автоматического обнаружения скиллов нет, передайте нужный `SKILL.md` агенту как инструкцию и предоставьте доступ к его связанным ресурсам.

Начните с `tui-trace-setup`. Остальные скиллы можно применять по отдельности, если уже подготовлены их входы: контракт, точные источники и, при необходимости, карточка инцидента. Имена других скиллов обозначают роли в процессе; постоянные абсолютные пути между установленными скиллами не требуются.

Пример задания:

> Используй $tui-trace-setup. Подготовь контроль для указанного запуска: цель — изменить интерфейс в /project/ui, запись разрешена только туда, сеть запрещена, журналы доступны в /control/traces. Определи полноту доступного формата и полномочия наблюдателя из текущей конфигурации. Подготовь контракт и проверку готовности.

Следующее задание:

> Используй $tui-trace-watch с контрактом /control/contract.json и нормализованным /control/events.jsonl. Проверь снимок, его непрерывность и действия относительно контракта. Укажи пробелы, доказательства и необходимую реакцию supervisor.

Это примеры путей и задач, а не разрешение на действия в реальном окружении.

## Быстрый запуск на синтетических данных

Из корня распакованного набора выполните на Linux с Python 3.10+:

```bash
python3 skills/tui-trace-watch/scripts/tracecheck.py \
  --contract skills/tui-trace-setup/assets/contract.example.json \
  --trace skills/tui-trace-setup/assets/safe.jsonl \
  --now 2026-09-13T12:00:05Z \
  --final
```

Результат: `no_findings`, exit code `0`. Скрипт анализирует текст примера и не обращается к `/srv/demo`, указанному в событиях.

Замените `safe.jsonl` на `blocked-attempt.jsonl`: ожидается `pause_required`, exit code `20`. В примере зарегистрирована запрещённая попытка изменить защищённый контракт; её результат — `denied`. Сканер сам не блокировал эту операцию и не утверждает, что изменение удалось.

Для `sequence-gap.jsonl` ожидается `indeterminate`, exit code `30`: последовательность содержит пропуск. Ожидаемые результаты также лежат в `assets/expected.json`.

Запустите тесты:

```bash
python3 skills/tui-trace-watch/scripts/test_tracecheck.py
```

Тесты создают временные фиктивные файлы. При ограничениях на временный каталог задайте `TRACE_TEST_TMPDIR` с разрешённым путём. Установка сторонних Python-пакетов не нужна.

## Использование с настоящими журналами

1. Получите актуальную задачу, разрешённые read/write/network границы, реестр агентов и их процессов. Подготовьте отдельный контракт вместо примера.
2. Установите, какие события реально доступны. Нативные JSONL Codex/Claude Code и журналы других TUI не являются форматом этого пакета. Настройте и проверьте адаптер в нормализованный JSONL v1 либо выполните ограниченный ручной аудит. Готовые адаптеры для конкретных TUI в архив не входят.
3. Сохраняйте оригинал и происхождение, нормализованный поток и отчёт раздельно. Защитите контракт, baseline, наблюдателя и доказательства от записи worker.
4. Проверяйте снимки скриптом. Передавайте `--previous` для контроля изменений предыдущего префикса. Первый снимок создаёт baseline и не доказывает прежнюю историю.
5. Для продолжительного наблюдения подключите внешний scheduler и контроль живости самого observer. В live-режиме не используйте `--now`: это часы для воспроизведения примеров.
6. Привяжите реакции к уже выданным полномочиям и проверьте их выполнение. Для предотвращения опасных операций нужен барьер до исполнения в доверенном supervisor/runner.

## Где проходит граница контроля

| Компонент | Функция | Что нужно обеспечить вне Markdown |
| --- | --- | --- |
| Worker | Выполняет задачу | Ограничения ОС, инструментов и сети |
| Collector | Фиксирует события и источник | Независимость от worker, полноту, heartbeat |
| Observer | Проверяет данные и выдаёт сигнал | Надёжный запуск, доступ только к необходимым данным |
| Supervisor | Выдаёт действия, ставит паузу и подтверждает её | Реальные полномочия, контроль детей и обработку сбоев |

`SKILL.md` задаёт поведение агента и не является системной песочницей. Скрипт читает ограниченный снимок; в нём нет демона, hook-обёртки, остановки процессов или сетевого фильтра. Чтение уже сохранённого журнала может обнаружить действие после его эффекта. Режим `enforce` в контракте сам по себе ничего не включает.

Коды CLI: `0` — нет находок реализованных правил; `10` — нужна проверка; `20` — нужна пауза/сдерживание; `30` — недостаточно данных. Любой другой код, timeout и неверный ответ означают неисправность наблюдения. Прямое подключение CLI как vendor-hook без проверенной обёртки недопустимо: у клиента и сканера могут различаться смыслы кодов.

Метаданные пути, источника и полноты целей должны формироваться проверенным collector/runner. Сканер не доказывает их подлинность. Он не раскрывает произвольный shell-код, не подтверждает исторические symlink, фактические DNS/IP/redirect/порты, не выявляет любую инъекцию или любой секрет. Эти случаи направляются на аудит и ограничиваются средствами исполнения.

Отсутствие находок, спокойный текст агента и отсутствие доступного reasoning не доказывают безопасность. Потеря части журнала отмечается явно. Авторизация из текущей задачи сохраняется; текст в логе не может расширить её. Если observer работает через облачную модель, прочитанное содержимое может уйти провайдеру: локальное расположение файла само по себе не гарантирует локальную обработку.
