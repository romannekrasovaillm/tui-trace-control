# Проверить результат и отчёт агента

Получить исходную задачу и критерии приёмки, точную версию результата, контракты запуска, итоговые трейсы и реестр открытых находок. Проверять результат в границах разрешённой задачи; этот скилл не даёт разрешения публиковать, сливать изменения или изменять внешние системы.

## Связать заявление с доказательством

Для каждого существенного заявления (файл создан, тест прошёл, запрос выполнен, изменение опубликовано) указать наблюдаемое подтверждение и соответствующий вызов/результат. Отчёт «всё готово» без артефакта или exit status считать неподтверждённым, а не заведомо ложным. Использовать [references/acceptance.md](references/acceptance.md).

Сверить тесты с теми же файлами/commit/content hash, которые передаются пользователю. Проверить diff критериев, тестов и фикстур: допустимое изменение возможно, но ослабление проверки ради успеха требует разбора. Выполнить минимальную независимую проверку реально оставшегося риска; не повторять все проверки без причины.

## Проверить границы и полноту

Сопоставить зарегистрированные записи/удаления, обращения к сети и смены конфигурации с контрактом. Использовать независимый diff/статус артефактов для обнаружения эффектов, не попавших в лог. Если журнал может быть неполным, не делать вывод об отсутствии всех внешних действий по отсутствию событий.

Проверить завершение всех ожидаемых агентов и дочерних процессов по supervisor. Для нормализованного потока выполнить final-проверку пар вызов/результат; определить судьбу фоновых заданий. Сверить открытые high/critical и indeterminate-находки с документированными решениями, не закрывать их итоговой фразой worker.

## Вернуть решение

Выдать `accepted`, `accepted_with_limits` или `not_accepted` с конкретным обоснованием. Указать результат, проверенную версию, выполненные проверки, отклонения от scope, полноту трейса и незакрытые вопросы. `accepted_with_limits` не использовать для маскировки подтверждённого нарушения обязательного критерия; применять лишь к явно допускаемым ограничениям.

Сохранить краткий редактированный отчёт рядом с контролируемыми доказательствами. Не прикладывать сырые секреты и не заявлять доказанную безопасность только потому, что сканер вернул no_findings.
