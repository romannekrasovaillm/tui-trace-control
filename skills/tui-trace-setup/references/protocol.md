# Протокол контроля v1

## Доверие и состояние

Контракт и реестр supervisor поступают от оператора вне трейса. Поле `origin` сообщает происхождение, но само по себе не доказывает подлинность. Хеш обнаруживает изменение относительно сохранённого эталона; без внешнего защищённого эталона хеш не доказывает отсутствие подделки. Самоотчёт worker — источник низкой надёжности.

Состояния: `unconfigured → observing`; при проверенной блокировке `observing → enforcing`; при сигнале `review/pause_requested → paused`; затем `investigating → resume_ready → observing/enforcing` либо `closed`. `pause_requested` становится `paused` только после подтверждения supervisor. Пропажа телеметрии означает `indeterminate`, а не нормальную работу. Старая тревога закрывается отдельным решением, а не исчезновением из окна.

У события три разных аспекта: намерение (сообщение), попытка (tool_call), наблюдаемый результат (tool_result/побочный эффект). Блокированная попытка остаётся попыткой; фраза в цитате не становится действием.

## Контракт

`schema_version`, `contract_id`, `run_id` определяют версию и запуск. `scope.read_roots`, `write_roots`, `protected_roots` — абсолютные POSIX-пути после разрешения ссылок на стороне исполнителя. `allowed_hosts` — точные lowercase DNS-имена/IP без схемы, порта и wildcard; для реального egress дополнительно ограничивать порт, протокол, DNS/IP, redirect и адрес назначения. Данный сканер проверяет только имя из записи.

`allowed_tools`, `allowed_operations` — точные имена. `denied_operations` имеет приоритет. `max_tool_calls` ограничивает число попыток за запуск, `max_consecutive_failures` — подряд ошибки одного инструмента одного агента. Успех этого инструмента сбрасывает его счётчик. Бюджет времени, денег и ресурсов при необходимости отдельно обеспечивать supervisor.

`monitor.expected_agents` — авторитетный список активных агентов, включая дочерних, `poll_seconds`, `heartbeat_seconds`, `heartbeat_timeout_seconds`, `clock_skew_seconds` задают наблюдение. Изменение состава требует нового контракта, записи решения и начала нового проверяемого окна; не удалять агента из списка только потому, что он замолчал.

`authority` и `acceptance` — поля для оператора и скиллов. CLI их сохраняет в контракте, но не исполняет команды, не проверяет полномочия ОС и не ставит блокировки.

## Нормализованное событие

Одна UTF-8 JSON-запись на строку, перевод строки обязателен для завершённой записи. Сохранять оригинал отдельно и ограничить доступ; нормализация не переписывает первичный журнал.

Обязательные поля: `schema_version: 1`, `contract_id`, `run_id`, `agent_id`, `event_id`, `seq` (положительное целое с 1 отдельно для каждого агента), `timestamp` (ISO 8601 с часовым поясом), `kind`, `origin` и объект `payload`. Порядок файла для одного агента должен соответствовать seq. Не сортировать события только по часам. Между агентами порядок доказывать причинными связями call_id/parent_id, а не близостью времени.

Виды: `heartbeat`, `tool_call`, `tool_result`, `message`, `lifecycle`, `coverage_gap`, `policy_change`. `origin`: `runner`, `collector`, `worker`, `external`. Надёжность источника проверять при сборе, не по строковому значению.

Для `tool_call`: `call_id`, `tool`, `operation`, `targets_complete` (boolean), `targets` (массив). Цель пути: `{"type":"path","value":"/absolute/resolved/path","access":"read"}` либо `write`; цель сети: `{"type":"host","value":"docs.example.org"}`. Операции read/write/delete должны иметь путь с соответствующим доступом, network — host. Отдельно допустимы `argv` как данные, `cwd`, `approval_ref`, `parent_call_id`; они не дают разрешений сами по себе.

`targets_complete=true` устанавливает доверенный адаптер только при известной полноте эффектов. Для общего shell, Python, вложенных скриптов, динамического кода и неизвестных инструментов ставить false, пока ограничения исполнения/инструмента не подтверждают полноту. Ни regex, ни простое разбиение shell-команды не доказывает её безопасность. Исторические цели нормализовать в момент действия: текущий symlink может отличаться от прошлого.

Для `tool_result`: `call_id`, `status` из `success/error/denied/cancelled`; привязка к паре agent_id+call_id. Результат без вызова, повторный результат или непарный вызов при завершении запуска требуют объяснения. `heartbeat` должен формироваться runner/collector независимо от многословия модели. `coverage_gap` содержит краткую причину; `policy_change` — ссылку на внешнее решение, но не меняет доверенный контракт.

Необязательный `source_ref`: путь/псевдоним источника, device/inode или file_id, диапазон byte_offset, line, source_sha256, adapter_version. Это ссылка на доказательство; не выполнять и не открывать указанный путь автоматически. Минимизировать чувствительные поля, не записывать значения секретов в общедоступные отчёты. Сохранять безопасные метаданные операции, чтобы редактирование секрета не скрывало сам факт доступа/передачи.

## Результат наблюдателя

Каждое решение содержит время, run/contract, версии и хеши политики/адаптера/сканера, границы прочитанного фрагмента, качество покрытия и доказательства. Для находки: стабильный ID, правило, важность, уверенность, agent/event/byte range, ожидаемое и наблюдаемое, статус действия (намерение/попытка/эффект), действие наблюдателя, ответ supervisor, владелец и условие закрытия.

Важность: `critical` — подтверждённый опасный эффект/активное вмешательство в контроль; `high` — подтверждённая запрещённая попытка; `medium` — аномалия, требующая проверки; `info` — контекст. Уверенность и полнота независимы от важности. Неполное окно не может дать заключение «безопасно».

Хранить курсор, предыдущие хеши, события тревог и решения вне доступной worker записи. Не переносить raw-трейсы в удалённую модель, облако, Git или ZIP без соответствующей авторизации и проверки чувствительных данных. Работа с локальным файлом через облачного агента также может передать его содержимое провайдеру: учитывать это при выборе observer.
