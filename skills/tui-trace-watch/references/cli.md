# Локальный сканер

`scripts/tracecheck.py` использует Python 3.10+ и стандартную библиотеку, рассчитан на POSIX с O_NOFOLLOW. Проверен в Linux. Он читает только явно заданные файлы, выводит JSON в stdout, не выполняет shell из данных, не пишет файлы, не отправляет сеть и не сигнализирует процессам. Пример контракта и JSONL находятся в других папках архива; для работы достаточно передать их пути.

```bash
umask 077
python3 /path/to/tui-trace-watch/scripts/tracecheck.py   --contract /trusted/control/contract.json   --trace /trusted/evidence/events.jsonl   --previous /trusted/control/report.previous.json   > /trusted/control/report.next.json
```

Первый запуск делать без `--previous`, затем сохранять последовательность отчётов. Не перенаправлять stdout в trace, contract или previous: оболочка усечёт файл до запуска. Следующий отчёт принимать как baseline только после сохранения и разбора; при инциденте сохранять прежний baseline. Если изменился контракт, закрыть старый интервал и начать явно документированный новый, не обходить проверку удалением previous.

| Exit | Verdict | Значение |
| --- | --- | --- |
| 0 | no_findings | Нет находок реализованных правил; это не разрешение на действие |
| 10 | review | Контекст требует проверки |
| 20 | pause_required | Найдена запрещённая попытка, нарушение лимита или изменение истории |
| 30 | indeterminate | Не хватает данных/полноты/актуальности или возникла ошибка ввода |

Любой иной код, timeout, отсутствие или неверный JSON — ошибка наблюдения. В verdict приоритет: pause_required, indeterminate, review, no_findings. Одновременно смотреть `coverage_issues`: высокий сигнал не устраняет пробелы.

`--now 2026-09-13T12:00:05Z` предназначен для воспроизведения фиксированных примеров; в live-режиме брать реальные часы наблюдателя, не время, предложенное worker. `--final` дополнительно требует результата для всех вызовов; в live открытые вызовы перечисляются количеством, их длительность отдельно контролирует supervisor.

Вход JSONL требует обязательные envelope-поля протокола v1. Контракт определяет read/write/protected roots, hosts, tools/operations, лимиты и ожидаемых агентов. Относительные пути целей, неизвестная операция, неполные targets или невалидная запись дают пробел покрытия. Поля message/reasoning CLI не классифицирует: семантический анализ выполняется отдельным аудитом.

Проверяются: размер/тип файла, отсутствие symlink в цепочке открытия, синтаксис/схема, уникальность ID и seq, часы и heartbeat, пары вызов/результат, scope, бюджеты, префикс предыдущего снимка и смена inode/контракта. Файл читается ограниченным префиксом; повторное чтение того же диапазона выявляет наблюдаемую гонку. Незавершённая последняя строка не считается обработанной и создаёт coverage_issue.

Ограничения: полный ограниченный снимок без дискового курсора и демона; stdout-отчёт может расти пропорционально числу событий в лимите. Ротация не восстанавливается автоматически. Скрипт не доказывает подлинность событий, не раскрывает shell-эффекты, не подтверждает DNS/redirect/порты, не разрешает исторические symlink, не проверяет OS-права и не детектирует любые секреты. Worker с записью в контракт, previous или collector может подделать метаданные. `targets_complete` не является доказательством само по себе. `example_only` — метка шаблона; оператор обязан заменить пример до реального контроля.

Запуск регрессии: `python3 /path/to/tui-trace-watch/scripts/test_tracecheck.py`. Данные создаются во временном каталоге и не запускают команды из трейсов. При ограниченном окружении задать `TRACE_TEST_TMPDIR` как разрешённый временный каталог. Запись/удаление родителя защищённого каталога тоже отмечается как protected_path_target.
